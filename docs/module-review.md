# 分模块审查与修复记录

> 阶段记录：以下内容描述记录当时的工作和验证范围。现行使用与开发说明见[文档目录](README.md)。

2026-09-25，基于当前工作区，保留原有未提交修改。本文记录本次连续审查中已落实的修复及验证边界；不是对所有平台、真实数据源或真实媒体库的完整验收。未提交或推送。

## 文件归属、删除与清理

- `media_files.rs` 统一判断目录归属：资料库根、共享目录、重叠条目、未归属视频、符号链接不能取得独占目录权限。
- 删除先校验整批目标。共享电影目录只回收选中视频；共享剧集目录拒绝整体删除；回收成功后才删除对应数据库记录。
- 回收失败不再降级为永久删除。Windows 补齐通过系统 FileSystem API 发送到回收站的实现，参数通过环境变量传递；尚未在 Windows 实机验证。[Microsoft API 文档](https://learn.microsoft.com/en-us/dotnet/api/Microsoft.Visualbasic.fileio.filesystem.deletefile?view=net-10.0)。
- 残余清理执行前重新确认文件归属，跳过共享目录，不误删同目录其他电影的字幕；逐文件检查取消。
- 队列和直接变更入口共用互斥锁；同一数据目录增加进程文件锁，防止多个 Sula 进程同时写入。外部文件管理器不受此锁约束。

## 扫描与数据库

- 增量扫描保留覆盖变化的浅层根，修复父目录新增视频与子目录同时出现时漏扫父目录文件的问题。
- 扫描前检查根可访问性，I/O/权限错误不作为删除依据。排除规则变化清空增量状态；仍存在但被排除的内容保留元数据。
- 保存枚举前观察到的目录状态，扫描期间新变化留待下次处理。快速退出不再刷新上次实际扫描时间；超过 24 小时的目录在用户下次刷新时重新枚举，补偿不可靠的目录时间戳。
- schema v3 保存根目录身份（Unix 设备号/inode，其他平台创建时间）；同一路径被替换时阻止扫描删除。扫描关键删除点再次检查。首次建立基线前的离线状态及保持相同身份的网络服务端异常仍不能可靠识别。
- 主季目录消失而其他平铺季仍在时，重新定位剧集根并保留条目 ID。
- 目录遍历、媒体枚举、分集核对支持合作式取消；取消不回滚已完成条目，不强制中断底层同步系统调用。
- 分集仅在文件确实不存在时删除；保留排除目录、其他平铺季、纯远程分集。重复季集文件报告歧义。分集增删改与季集数在同一事务提交，保留已有元数据和 ID。
- schema 迁移使用事务；版本 2 为操作日志表，版本 3 为根目录身份表。未对用户实际数据库运行迁移。

根目录身份改变时需恢复原挂载；确实换盘时重新绑定到新路径或重新添加资料库。不会自动接受陌生目录并清除原索引。

## 整理、重命名与恢复

- 共享电影目录只整理视频及最长匹配文件名前缀所属的伴随文件；不移动资料库根或其他电影。
- 媒体模板整理先规划最终路径，检查源、目标、符号链接和重复目标，再逐文件移动；每个文件最多移动一次。
- 电影/剧集模板整理、重复剧集合并都接入 SQLite 文件操作日志。每次移动前记录源、目标和文件身份；数据库引用更新与提交标记处于同一事务。
- 普通失败逆序回退；重启恢复未提交操作，已提交操作只清理日志。遇到文件替换、冲突或无效日志时保留现场并阻止变更。
- 视频、字幕、剧照、季海报和条目路径同步更新。合并保留分集元数据；重复季集和目标冲突不再跳过后删除源记录。
- 回退只清理本次记录的空目录；成功后也只清理旧的空目录，不递归删除残留内容。
- 独立批量规则重命名与撤销使用各自的持久化快照，覆盖移动后未确认及撤销中断窗口。

恢复测试使用临时磁盘数据库和样例文件模拟退出窗口。SQLite WAL/NORMAL 与文件系统移动不构成断电原子性保证；没有真实 kill/断电测试，非 Unix 文件身份也弱于 Unix。

## 刮削、NFO 与图片

- 电影 NFO、海报及其他图片采用视频专属文件名，避免共享目录相互覆盖；导入不借用其他电影的 NFO，NFO 内容采用匹配后的标题和年份。
- 图片各角色独立下载，某项失败保留其他成功结果并累计问题；季海报避免重复下载，失败时保留已有路径；剧照/NFO 写入问题作为部分完成报告。
- 共享剧集目录拒绝目录级元数据写入，图片和 NFO 使用原子文件写入。
- 整库刮削使用有界并发，完成即上报；单项失败继续批次。取消停止派发、终止并等待在途异步任务，保留已完成的结果计数。
- 选中项、重新刮削、手动匹配和单季刮削接入可取消队列。单季入队后不再提前显示“完成”。
- 代理配置日志不再输出可能包含口令的完整代理 URL。

真实四个数据源的限流、语言回退、匹配歧义与账号权限，需要真实服务验证。本地 HTTP 故障样例只证明部分图片失败处理，不代表数据源整体通过。

## 任务与配置

- 任务 panic 转成该项失败，不终止队列；恢复问题阻止后续文件变更。
- 整库、选中批次、整理、手动匹配和分季任务按操作及目标范围去重，避免仅按首个条目误合并不同批次。
- 任务历史原子保存，最多保留 256 条，优先淘汰已结束记录；全部占满且仍活动时拒绝新任务。启动将上次未结束任务标为中断，不自动重放变更。
- 损坏的历史文件保留备份后重建；刮削计数以成功/未匹配/失败的结构化字段展示。
- 损坏配置保留备份、恢复默认值并通知界面。配置写入失败保留旧磁盘内容和旧凭据引用；命令入口回退内存配置。
- API key 移到操作系统凭据库。旧明文配置首次加载时迁移；先存新凭据再提交不含密钥的配置，成功后清除旧引用。凭据服务不可用时报告错误，保留旧文件。
- 使用 [keyring 3.6.3](https://docs.rs/keyring/3.6.3/keyring/) 的 macOS、Windows、Linux 后端；Linux CI 补齐 DBus 开发依赖。凭据测试使用内存替身，没有访问真实钥匙串。

取消的边界是停止后续操作；已落盘的媒体文件和元数据保留。任务历史保存错误会报告到日志；它不替代文件操作恢复日志。

## 前端与样式

- 库列表和详情均使用请求版本检查，覆盖切库、同库重复加载、A→B→A 详情请求乱序。
- 列表每批 256 条读取并渐进显示，后端上限 512；稳定排序和前端按 ID 去重。搜索/排序仍在客户端，全部元数据最终仍驻留内存。
- 独立 `VirtualMediaList` 只挂载可视范围和少量预留行，支持网格/列表、尺寸变化以及方向键/Home/End 导航。
- 海报 Promise 缓存限制为 512 条 LRU；无图/失败可重试，失效通知和版本检查阻止旧响应覆盖新图，失效的排队请求不再发 IPC。
- 事件订阅、主题启动及主题 watcher 清理处理异步卸载，避免旧订阅注销新订阅。
- 已移除外部设计锁、生成 CSS、token CSS、边界检查脚本、构建钩子、CI 外部设计仓库依赖及组件 profile。`index.css` 直接维护布局/字号/圆角/组件，`appearance.css` 只维护软件自己的主题、强调色和动态布局变量。

保留现有 App/store 业务结构，已抽出虚拟列表职责；继续拆文件属于后续结构优化，不以机械拆分替代功能修复。
